# GhostC — modular Minecraft 1.8.9 client

**Milestone R2.22:** Java 8-compatible core, Forge adapter, original ClickGUI/HUD and shared gameplay service contracts. **Windows/in-game launch and visual fidelity are not yet verified.**

## What is implemented

- Host-independent registry, module lifecycle, typed settings, owner-thread policy, bounded event queue and profile persistence.
- `HostRuntime` receives client tick/render/input/world/disconnect transitions, isolates them from Minecraft objects, and persists toggles.
- Forge `@Mod` adapter under `forge189/`: world-only status/metrics HUD, F8 status toggle and F7 ClickGUI.
- New searchable ClickGUI: categories, settings, keybind capture, themed wide/compact layout; HUD editor with normalized positions and atomic preference persistence.
- R2.22 translucent Filled Box ESP: adds `filled_box` and `filled_skeleton` styles after the original seven ESP choices, with six transparent 3D bounding-box faces and a full RGB wire outline (optionally schematic skeleton). New `fill_opacity` slider 4–50% (default 18%) multiplies the existing RGBA opacity so fill and outline can have different transparency without changing the previous seven styles. The first-party Java8 `EspFilledBoxGeometry` checks finite and plausible-size bounds before nearest-80 admission, and emits exactly six quads / 24 vertices through a reusable sink with guarded `GL_QUADS`. Old style IDs/defaults, HP gauge, depth/through-wall controls, GL state guard, and profile schema remain intact. Tests cover 12,000 seeded boxes, all faces and slider/profile persistence; actual onscreen Forge render behavior remains unverified.
- R2.21 first-party 3D Corner Box ESP: adds optional `corner_box` and `corner_skeleton` styles to the existing Player ESP style cycle without reordering its previous five modes or changing the default. A new persistent `corner_length` slider (10–50% of the corresponding box dimension, default 26%) controls short inward-looking X/Y/Z arms at each of eight player bounding-box corners, rather than drawing the twelve complete Box edges. The new pure Java8 `EspCornerBoxGeometry` validates finite/nondegenerate player bounds before a candidate can enter the nearest-80 render selection, and emits exactly 24 GL line segments through one guarded batch without per-player arrays. Corner styles use R2.20 RGBA coloring, keep optional HP bars and existing depth/through-wall behavior, and share all original owner/fault safeguards. Regression covers 15,000 seeded geometries, seven mode decisions, slider settings and persisted style/length. Real Minecraft screen output remains unverified.
- R2.20 first-party customizable Player ESP appearance: the original Box, Tracer and schematic Skeleton line work previously used one hardcoded purple OpenGL tint. All five ESP modes now share persistent normalized `red`, `green`, `blue`, and `opacity` sliders inside the existing Player ESP settings. Defaults exactly preserve R2.19 purple and 82% opacity, with a valid alpha range 0.1–1.0 and channel range 0–1. The optional health gauge keeps its semantic red–green health fill rather than adopting the line tint. Color values are resolved once per render frame, with no per-player array allocations, and remain subject to existing owner-thread, profile validation and Forge GL restoration rules. Tests cover saved-profile round trips and 25,000 seeded RGBA combinations. This is source/CI-verified, not visually accepted in Minecraft yet.
- R2.19 bounded-rank profiler overhead reduction: Source audit found that `SnapshotTelemetry.snapshot()` recalculated p50/p95/p99 with three **4,097-bin linear scans** on every diagnostics HUD frame, once for aggregate timing and again for the last demand mode. Replaced with fixed-memory Fenwick order-statistic lookup (~13 steps per quantile and ~13 updates per sample), preserving the original exact nearest-rank percentages, 4096+ µs overflow bucket, uncapped elapsed maximum, four demand-mode partitions and strictly numeric opt-in export fields. Immutable per-bucket snapshot caching removes repeated recalculation and allocation when no new data arrived. The 72,000-sample independent regression oracle exercises all modes, extreme duration values, owner-thread isolation and report compatibility. This is bounded complexity validated offline, not a measured game FPS improvement.
- R2.18 classified snapshot profiling and focus isolation: R2.17's one aggregated p95/p99 distribution mixed off/visible-only/unfiltered/mixed target modes and included samples while Minecraft menus/chat/alt-tab had blocked input. The profiler now preserves the original numeric aggregate report and adds four separately bounded demand-class histograms and exported `snap.mode_*_` numeric fields; the diagnostics HUD identifies the last sampled mode and that mode's own p95/sample count. The Forge profiler starts only with Runtime Diagnostics enabled and the game in focus; no focus-blocked work is sampled. New tests verify 16,000 classified samples, privacy, ownership and mode counts, preservation of the old report keys and omission of menu samples. These are preparation for a comparable in-game benchmark, not measured FPS improvements.
- R2.17 opt-in snapshot work profiler: actual Forge client END-tick snapshot construction now produces a bounded 4,097-bin microsecond distribution (p50/p95/p99, uncapped max), as well as scanned-player, in-range, line-of-sight-query and published-target totals. Collection is strictly gated by the existing Runtime Diagnostics module, occurs only after a successful immutable snapshot publish, and exports numeric-only `snap.*` aggregates in the standard optional local acceptance report. The diagnostics HUD displays snapshot timing and workload next to the existing FPS/JVM-heap and ESP counters. Deterministic tests cover 16,000 replayed samples, privacy, opt-in behavior and quantile consistency. This is measurement instrumentation, NOT a claim of improved FPS or real gameplay testing.
- R2.16 independent target radii and allocation-free selectors: split snapshot LOS-gating by each active visibility preference's actual maximum radius. In mixed modes with a 24-block unfiltered HUD and six-block visible-only Aim Assist, only the inner six-block players now require LOS rays; distant HUD candidates still enter the unfiltered partition without extra rays. In the opposite configuration, the 24-block visible-only HUD still receives its full set, while hidden targets past unfiltered aim radius are excluded. Target HUD now scans for its nearest target without a sorted list, and Aim Assist scans eligible snapshot entries directly without materializing/sorting up to 512 candidate records each tick. Deterministic tests compare the new selectors against the original sorted path across 1,800 seeded worlds and 18,000 demand cases. No live FPS or gameplay parity is claimed.
- R2.15 demand-aware snapshot cost containment: the R2.14 Forge END-tick publisher performed LOS rays on every eligible loaded player regardless of whether Target HUD or Aim Assist was enabled, and regardless of the configured target range. The new first-party `SnapshotDemand` policy computes the active 24-block-maximum HUD and 6-block-maximum Aim Assist radius once per tick and rejects out-of-range candidates before LOS queries. If neither target consumer is enabled, it skips enumeration and still publishes an **empty valid** tick snapshot for unrelated combat safety gates. An unfiltered-only consumer performs **zero LOS rays** and uses just one capped nearest-256 group; visible-only and mixed modes preserve accurate visibility and original nearest-target semantics with up to 512 combined candidates. Deterministic tests cover 18k demand combinations and 1,350-player scenes; real FPS remains unmeasured.
- R2.14 visibility-aware target snapshot admission: fixes another crowded-world starvation case: an otherwise nearer 256-person group hidden by walls could exclude every visible Target HUD or Aim Assist candidate from the shared snapshot, despite their `visible_only` setting. Forge now retains the nearest 256 visible **and** nearest 256 nonvisible candidates in a reusable owner-thread partition, merging by distance/ID before constructing the immutable snapshot (512 max). Explicit duplicate-ID handling favors admitted visible records and nearer duplicates; raw player references are released after each publication. Target selectors and existing GUI/settings keep their semantics, and ESP still independently renders only its nearest 80. Tests cover 800 crowded players, target visibility, shuffled input, 190-tick churn and privacy boundaries; no in-game behavior is claimed.
- R2.13 nearest-256 shared world snapshots: Target HUD and Aim Assist previously used only the first 256 valid players encountered in Minecraft's arbitrary loaded-player list. The Forge snapshot publisher now uses the existing nearest-first bounded owner-thread buffer at capacity 256, validating finite pose, positive health and distance before admission. Its output is a newly built immutable snapshot, and raw player references are always cleared in a finally block. ESP retains its independent 80-player render cap. New deterministic regression covers 700 loaded players with near targets at the end, 128 shuffled lists and 250 simulated crowded-world ticks; real Minecraft gameplay acceptance is still outstanding.
- R2.12 nearest-player ESP priority: the 80-player per-frame cap now uses a deterministic nearest-first selection instead of trusting the arbitrary order of Minecraft's loaded player list. A reusable, owner-thread-only bounded buffer orders candidates by squared distance and entity ID (stable ties), rejects duplicates/invalid distances, and clears entity references after each render. All pre-existing filters and full finite geometry/skeleton validation run before admission, so an invalid or distant candidate cannot consume the available 80 slots. All five ESP styles and the optional health bars share the same closest-player selection. Core tests verify order invariance with 280 shuffled populations and a 1,000-frame replay; in-game visibility remains unverified.
- R2.11 optional ESP health bars: adds a GUI-toggleable, persisted `render.esp.show_health` option (disabled by default for legacy profile compatibility) alongside all five pre-existing ESP styles. First-party, allocation-free camera-facing vertical health geometry (background plus green-to-red fill) works beside boxes, tracers and skeletons, honors existing depth/through-walls, and skips malformed health/width/view data without disabling valid ESP primitives. Includes seeded 14,000-pose geometry and cross-style wiring tests; actual Minecraft visual fidelity remains unverified.
- R2.10 focus and warning visibility hardening: END-tick focus admission now suspends FPS timing even when Forge stops issuing 2D overlay callbacks in a GUI. The owner runtime rejects performance samples while its input focus is blocked, and unadmitted world/player overlay events clear timing references. Reversed/overflowed monotonic timestamps are counted separately rather than corrupting FPS bins. Fault/profile/UI/diagnostics warnings appear even when both Status and Metrics modules are disabled, using bounded fallback positioning. Offline tests model no-overlay GUI gaps and 13,000 seeded viewport sizes; live Minecraft startup/visual acceptance still needs real evidence.
- R2.9 active gameplay performance telemetry: optional diagnostics now samples actual Forge overlay callback intervals into a fixed 1001-bin FPS histogram (min/p50/p95/p99/max, rounded FPS), and tracks sampled JVM heap/peak MiB. GUI/chat/focus/world changes or turning diagnostics off suspend the interval timer. Counts and heap aggregates export as safe numeric fields in the existing Windows acceptance report; no process, player, server or chat data is retained. These measure callback cadence rather than confirmed displayed pixels, GPU timings or a completed gameplay soak.
- R2.8 in-game ESP diagnostics bridge: counts actual client-thread ESP renderer frames, submitted player draws, submitted skeleton draws, and rejected invalid geometry without retaining player names, locations or server details. The in-game opt-in diagnostics HUD and local counter-only export surface those counts. Validates both current and previous skeleton body yaw, render interpolation fraction and height on **all** ESP modes before GL vertices are issued. Adds a versioned acceptance checklist to cross-check visible results, but no automated test claims a successful Minecraft GUI launch.
- R2.7 original skeleton ESP: adds selectable `skeleton` and `box_skeleton` modes alongside the existing `box`, `tracer`, `both`. A first-party Java-8-compatible body-oriented schematic 15-bone player overlay supports interpolation, movement swing and crouch. Rendering retains the existing visibility, depth, range, style and OpenGL guards. Only fully validated players count against the per-frame 80-player cap. Deterministic 14,000-pose regression replays and JAR class-inventory checks are included; visual results remain unverified in game.
- R2.6 recovery transaction and bounded read: the actual input stream is capped at 1 MiB (including concurrent growth); legacy schema-1 files are also limited to 4096 parsed fields. Failed typed validation of a backup can no longer modify live module or UI settings before file recovery succeeds. Restoration promotes the **same exact staged and validated backup bytes** rather than applying one revision and restoring another.
- R2.5 typed backup validation: profiles and UI backups are checked against the **same complete typed settings parser used at load time**, in addition to the canonical SHA-256 digest. Correctly sealed but unloadable keybinds, enums or HUD positions can no longer replace a known-good .bak. Both success and negative paths are regression-tested.
- R2.4 backup rotation hardening: module-profile and UI saves now verify the exact staged source bytes, canonical digest and schema before replacing the prior .bak. A damaged or legacy unsealed primary can be overwritten with a new healthy save **without poisoning the last verified backup**; atomic promotion and temporary-file cleanup protect existing backups. Seeded corruption-and-save regression tests and Forge source contracts prevent reintroduction.
- R2.3 config resilience: modern module profiles and UI preferences include a canonical SHA-256 corruption check while legacy schema-1 files remain readable. Startup can restore validated .bak copies without overwriting the only good backup, preserving damaged originals as .corrupt. Oversized config files and malformed digests are rejected before any state mutation.
- R2.2 bounded Status/Metrics renderer: measure the combined Status/FPS/XYZ footprint so metrics-only HUDs and long coordinates remain screen-anchored. Status and Metrics now render through separate fault guards, and the F7 editor uses their measured footprint. Includes seeded geometry and independent fault-isolation regression coverage.
- R2.1 accessible HUD controls: dedicated Status/Keys/CPS/Target selector tabs, one-pixel arrow nudges (Shift+Arrow 10 pixels), and a reset action. Live editor previews and the actual Forge renderers now share settings-dependent Keystrokes/Target HUD heights, preserving normalized anchors and UI schema-1 persistence.
- R2.0 viewport-accurate HUD editor: a letterboxed representation of the actual Minecraft scaled screen replaces the stretched editor canvas; preview widget footprints, normalized drag coordinates and rendered anchors now share a pure geometry model, with automatic status size/scale parity. This corrects visual misplacement on widescreen aspect ratios while retaining all R1.9 widget preferences.
- R1.9 multi-widget HUD editor: Keystrokes, CPS and Target HUD now have separate draggable normalized anchors alongside the original Status HUD. The existing UI profile schema and status position remain backward-compatible; new coordinates are validated and persisted atomically. Forge renderers consume these anchors instead of hardcoded screen offsets.
- R1.8 reserved shortcut safety: the global F7 ClickGUI key can no longer be assigned to modules through direct binds or imported profiles, while the existing F8 status shortcut remains supported. The capture dialog now lets F7 close the GUI. A deterministic 10k-key replay and negative profile tests verify rejection without partial changes.
- R1.7 Compact GUI recovery: replaced the impossible 445px minimum (Compact maxes at 390px) with geometry-derived safe boundaries so Compact and Wide both work; reconciles selected module with current search/category results, preventing hidden settings/keybinding edits and handling zero results safely. Automated tests validate resize/toggle behavior and 25k seeded selection transitions.
- R1.6 ClickGUI chrome safety: header tabs/layout/theme controls and sidebar category clicks share exact visible geometry, while undersized scaled viewports display a resize notice and disable ambiguous controls. The module registry now retains exception types without private exception messages; both behaviors are protected by new Java and Forge-wiring tests.
- R1.5 immediate render/input admission: reject mouse and both 2D/3D render callbacks that arrive after an unadmitted world/player swap but before the next END tick; visible-row-only ClickGUI module and setting hitboxes, bounded wheel regions and reliable small viewport click handling. New seeded `ViewportHitTests` and Forge wiring gates guard against regressions.
- R1.4 session correctness: detect world/dimension/local-player object identity replacements without an empty-world tick, invalidate both old session generations and stale snapshots, skip malformed player poses, and reject nonfinite ESP geometry before calling OpenGL. All backed by direct Forge wiring and seeded lifecycle regression tests.
- R1.3 combat reliability: independent Java exception quarantine for Aim Assist, AutoClicker, Hit Select and Block Hit with fail-closed action/camera intent cancellation. Enhanced pure-Java session/fault replays and real Forge combat wiring checks, plus one shared mod version constant for both in-game HUD labels.
- R1.2 Forge feature wiring reconciliation: all HUD features, 3D ESP and Auto Sprint are once again routed through `HostRuntime.runFeature` with per-feature exception quarantine; independently guarded OpenGL state, visible sanitized fault warning and remapped Minecraft key labels.
- New Java/Python regression gates verify both the pure feature fault behavior and its actual Forge source wiring so later refactors cannot silently bypass the guard. **In-game rendering, input and stability remain unverified.**
- R1.1 ClickGUI viewport fixes: search hitboxes and focus rebind on scaled-screen changes; HUD editor preview and list geometry cannot exceed the window, and F7 can also close the GUI.
- Opt-in real-Forge callback evidence counters (GUI open/frame/close, overlay/world render, key/mouse events), saved as aggregates without names, chat or coordinates. In-game behavior remains unverified until a real client session records them.
- R1.0 Windows acceptance tooling in GitHub: SHA-256-gated install, owned-JAR backups, safe rollback, redacted counter-only evidence checklist and a CI-tested transaction against a fake Windows profile. This does **not** launch Minecraft automatically.
- Full JAR verification in CI: ZIP CRC, duplicate/unsafe archive entries, every Java class' Java-8 bytecode, required Forge entrypoint and matching mod metadata, tested on Linux and Windows.
- R0.9 stability: fault containment for Forge visual and Auto Sprint callbacks; failing features are disabled, persisted and reported without retaining exception messages. HUD keystrokes reflect actual Minecraft keybindings, not hardcoded WASD labels.
- New independent Windows JDK8 ForgeGradle build smoke gate, checks versioned Java 8 mod entrypoint and key classes; Windows GitHub runner is **not** a licensed Minecraft launch.
- R0.8 runtime safety: physical-release admission before automated combat pulses after GUI/focus/world changes, conflicting/unbound F7 keybind rejection, single-authoritative world readiness at END client tick and scheduled network disconnect callbacks on the Minecraft owner thread.
- Opt-in `hud.diagnostics`: nonidentifying tick/focus/session/action counters visible in game; on disconnect or close, writes `.minecraft/config/ghostc/diagnostics-last.properties` with a backup and no user/server metadata.
- Two additional opt-in combat controls: **Block Hit** (bounded sword-only USE pulses while attack is physically held, delayed when an extra attack pulse is queued) and **Hit Select** (target-hurt-time and minimum-tick-gap filtering of **AutoClicker-generated extra presses only**). Neither suppresses manual attacks; integration is Forge-CI-tested, not in-game verified.
- Two opt-in combat modules: bounded Aim Assist (local camera, FOV/range/speed/visible/hold-gated) and deterministic hold-to-click AutoClicker (CPS and optional entity-only constraint) through shared G3 owner-thread arbiters. No anticheat evasion or packet injection, and game runtime unverified.
- Five first-party functional modules: keystrokes, CPS counter, nearby-player Target HUD, player box/tracer ESP, and Auto Sprint. Forge code provides actual rendering or local player sprint requests, while testable pure-Java policies own filtering and telemetry. **In-game behavior is unverified.**
- Shared pure-Java services: read-only player snapshots and selection, rotation/action arbitration, packet-intent completion, serial inventory intent, session generation fencing. **Camera correction and vanilla attack-key intents exist; no Netty packet interception or manipulation.**
- Offline core, host, UI, service, feature and combat regression tests run in GitHub Actions for JDK 17/21; separate legacy ForgeGradle CI produces a reobfuscated mod JAR on JDK 8.

## GitHub builds

- [Core CI](../../actions/workflows/core-ci.yml) — headless Java core artifact, **not a mod**.
- [Forge 1.8.9 CI](../../actions/workflows/forge189-ci.yml) — builds `ghostc-forge189-*.jar` using ForgeGradle 2.1 and Forge 11.15.1.2318; when successful, the artifact is labeled **unverified in-game**.
- [Forge acceptance instructions](docs/FORGE189.md) — exact versions and testing boundaries.

For standalone core offline testing, with JDK 17+:

```bash
mkdir -p .build/classes .build/tests
javac --release 8 -d .build/classes $(find src/main/java -name '*.java')
javac --release 8 -cp .build/classes -d .build/tests $(find src/test/java -name '*.java')
java -cp .build/classes:.build/tests dev.ghostfusion.tests.CoreTests
java -cp .build/classes:.build/tests dev.ghostfusion.tests.HostRuntimeTests
java -cp .build/classes:.build/tests dev.ghostfusion.tests.UiTests
java -cp .build/classes:.build/tests dev.ghostfusion.tests.ServicesTests
java -cp .build/classes:.build/tests dev.ghostfusion.tests.FeatureTests
java -cp .build/classes:.build/tests dev.ghostfusion.tests.CombatTests
java -cp .build/classes:.build/tests dev.ghostfusion.tests.CombatMoreTests
java -cp .build/classes dev.ghostfusion.demo.DemoMain
```

For Forge builds use **JDK 8 + Gradle 4.10.3** and `gradle -p forge189 build`. This old Gradle / ForgeGradle toolchain may have external repository compatibility issues; CI results take priority over assumptions.
